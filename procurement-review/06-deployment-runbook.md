# Deployment & Operations Runbook (loopback prototype → VPS)

> **Advisory decision-support system.** AI flags/drafts/recommendations never
> finalize statutory procurement decisions; named humans decide and sign.

## 1. Services (all loopback-only)

| Service | Started with | Port | Binds |
|---|---|---|---|
| Review UI | `python review_server.py --db procurement.db [--auth-token TOKEN] [--tls-cert/--tls-key]` | 8091 | 127.0.0.1 only |
| COA verification (read-only) | `python coa_server.py serve --db procurement.db [--auth-token TOKEN] [--tls-cert/--tls-key]` | 8090 | 127.0.0.1 only |
| Extraction stub (tests) | `python training_adapter.py serve-stub --port 8080` | 8080 | 127.0.0.1 only |
| Extraction adapter | `python model_adapter_server.py --upstream-kind ollama/openai/llama_cpp --upstream-url http://127.0.0.1:... --model <name>` | 8092 | 127.0.0.1 only |
| Model plumbing check | `python model_plumbing_check.py check --url http://127.0.0.1:8092/extract` | — | loopback URL only |

Non-loopback binds are refused in code. For LAN/VPS access, put an
authenticated reverse proxy in front (proxy auth + TLS) — do not expose
these ports directly.

### 1.1 TLS / mutual TLS (code-side hardening)

Both HTTP services accept operator-supplied TLS via `ops_tls.py`:

```bash
# Review UI (env fallbacks: REVIEW_TLS_CERT / REVIEW_TLS_KEY / REVIEW_TLS_CLIENT_CA)
python review_server.py --db procurement.db --auth-token "$REVIEW_AUTH_TOKEN" \
  --tls-cert ./certs/review.pem --tls-key ./certs/review.key

# COA verification (env fallbacks: COA_TLS_CERT / COA_TLS_KEY / COA_TLS_CLIENT_CA)
python coa_server.py serve --db procurement.db --auth-token "$COA_AUTH_TOKEN" \
  --tls-cert ./certs/coa.pem --tls-key ./certs/coa.key

# Mutual TLS: clients must present a certificate signed by this CA
python review_server.py --db procurement.db \
  --tls-cert ./certs/review.pem --tls-key ./certs/review.key \
  --tls-client-ca ./certs/agency-client-ca.pem
```

- Certificates/keys come from the agency PKI/CA; nothing is generated by the
  code, and keys must never be committed or copied into backups/sealed folders.
- Half-configured TLS (cert without key, or a client CA without a server cert)
  **fails closed** — the service refuses to start rather than serving plaintext.
- TLS 1.2+ only. HSTS is sent when TLS is active; all responses also carry
  CSP/no-sniff/frame-deny/referrer/COOP/CORP/permissions-policy headers.
- TLS protects transport only. Statutory decisions still require named human
  sign-offs, and `--auth-token` remains a prototype shared secret — replace it
  with agency SSO at the reverse proxy for production.
- For any non-loopback exposure, terminate TLS at the authenticated reverse
  proxy (with agency IdP) and keep the app itself loopback-bound.

## 2. Review queue operations

```bash
cd procurement-core
python review_queue.py list --status OPEN
python review_queue.py dashboard
python review_queue.py export --out review-queue.html
```

Role-aware actions (enforced via `review_queue.ROLE_PERMISSIONS`):
claim/recommend/resolve (BAC roles), override → correction (BAC_STAFF /
SECRETARIAT / TWG), adjudicate (SECOND_REVIEWER / CHAIR / SECRETARIAT;
submitter can never self-adjudicate). The CLI `adjudicate` exposes
`--actor-role` with the same allowlist, and review-action POSTs are capped at
1 MiB (unknown POST paths are rejected before the body is read).

named-human steps via `learning.py`. Rollback restores the prior version.

## 5. Backup / restore drills / retention

```bash
python ops_backup.py backup --db procurement.db --out backups/db-<date>.db
python ops_backup.py verify  --backup backups/db-<date>.db
python ops_backup.py restore-drill --backup backups/db-<date>.db --restore-to /tmp/restore.db
python ops_backup.py retention --db procurement.db
```

Drills verify the hash chain + corpus integrity on a COPY; they never touch
the live database. Sealed folders + ledger are retained indefinitely (WORM).

## 8. Deployment smoke check (read-only rehearsal)

```bash
# database-only checks
python ops_smoke.py --db procurement.db

# include live loopback services
python ops_smoke.py --db procurement.db \
  --review-url http://127.0.0.1:8091/health \
  --coa-url http://127.0.0.1:8090/health
```

Verifies the ledger hash chain, corpus passage hashes, seed/registry readiness
(advisory info) and optional service `/health` endpoints. It never writes to
the database or makes decisions; exit code 0 means every error-severity check
passed — readiness blockers are reported but remain expected fail-closed state
for the prototype.

## 9. PostgreSQL migration scaffold (stdlib-only dump generator)

Python's stdlib has no PostgreSQL driver, so the code-side migration path is a
deterministic dump generator; the actual load/verify on PostgreSQL is an
operator step on the approved target environment.

```bash
cd procurement-core

# 1. verify the source before anything else (fail closed on chain/corpus/FK errors)
python ops_migrate_pg.py verify-source --db procurement.db

# 2. export the deterministic PostgreSQL dump (schema + data + manifest)
python ops_migrate_pg.py export --db procurement.db --out pg-migration.sql

# 3. self-check the dump (replays INSERTs into scratch SQLite, re-verifies chain)
python ops_migrate_pg.py check-dump --db procurement.db --dump pg-migration.sql

# 4. operator step — load on the approved PostgreSQL target
psql "postgres://user@host/procemp" -1 -v ON_ERROR_STOP=1 -f pg-migration.sql
```

Notes:
- The dump embeds `schema_pg.sql` (PostgreSQL DDL mirroring `schema.sql`;
  parity is enforced by `tests/test_migration.py`). Append-only ledger,
  immutable pinned fields, WORM sealed folders and frozen benchmarks are
  enforced by PostgreSQL triggers, same as SQLite.
- Ledger `seq`/`row_hash` are preserved byte-exactly and the identity sequence
  is re-anchored with `setval`.
- Post-load row counts are in the dump footer manifest; the commented
  `SELECT ... UNION ALL` count query at the end of the dump runs as-is in psql.
- Application-level chain re-verification on the PostgreSQL store needs a
  driver-based verifier (external step) — the dump preserves hashes to make
  that possible. Never edit a dump by hand; re-export instead.
